# コードレビュー方針

## 前提

- 言語: TypeScript / Node.js
- フレームワーク: NestJS
- ライブラリ: Slack Bolt
- 依存関係の正確なバージョンは package.json を必ず参照すること。
  バージョンによって挙動や非推奨APIが変わるため、推測で判断しない。

## レビュー観点

### 1. モジュールの組み方(NestJS)

- Module / Controller / Service / Provider などのクリーンアーキテクチャ的な観点で責務分離が適切か
- 循環依存(circular dependency)が発生していないか
- DIの使い方が妥当か(不要な直接インスタンス化をしていないか)
- 1つのServiceが肥大化・多責務化していないか

### 2. セキュリティ

- Slackからのリクエストの署名検証(Signing Secret)が行われているか
- 環境変数・トークン・シークレットがハードコードされていないか
- ユーザー入力(Slackコマンド、メッセージ本文等)のサニタイズ/バリデーションがされているか
- 権限チェック(誰でも実行できるコマンドになっていないか)が適切か
- ログに機密情報(トークン、個人情報)を出力していないか

### 3. 冗長性

- 同じロジックが複数箇所に重複していないか(共通化できないか)
- 不要な条件分岐、到達しないコード
- 過剰な抽象化・不要なラッパーがないか

## 出力フォーマット

- ファイル名・行番号・重要度(高/中/低)・指摘内容・改善案 を表形式で出力
- 重要度の高い順に並べる
